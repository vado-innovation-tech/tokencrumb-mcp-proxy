# Security policy

Report suspected vulnerabilities privately through the repository's **Security → Report a vulnerability** feature. If that feature is unavailable to your account, contact a repository maintainer privately through an existing trusted channel. Do not include exploit details or credentials in a public issue.

Include the affected commit, configuration, expected behavior, actual behavior and a minimal reproducer with synthetic keys and data. Never send operational private keys or live tokens.

Security fixes target the current development branch. No long-term support or response-time commitment is offered for older revisions.

Read the [security model](docs/security-model.md) for supported trust boundaries and deployment assumptions.
